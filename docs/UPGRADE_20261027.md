# 2026-10-27 local upgrade: proposition boundaries

Base commit: e02cea6f05158f7a4ac895794a8cca7b882b44c2.
This is a local reviewable upgrade, not a deployed release.

## Observed problem and decision

An uncertainty marker anywhere in a punctuation-delimited clause caused the
event guard to skip the whole clause. Thus an unsupported event-impact claim
could pass when followed by an unrelated uncertainty statement across a
contrast/addition connector. Eight authored negative examples reproduced it.

Retain the existing evidence engine, data, model integration, UI, export and
request gate. Split known contrast/addition connectors before the existing
dataset-specific checks. Change the policy cache version so old accepted
results cannot reuse the previous policy identity. Add a challenge fixture,
an offline evaluation script, one unit-test method iterating the fixture,
and a CI step. This is narrow regression protection, not semantic fact checking.

## Reproduce

Use the project's existing requirements. Python 3.10 with installed dependencies
was used for the current local run; existing CI targets Python 3.11.

```text
python -m unittest discover -s tests -v
python tools/evaluate_analysis.py --output artifacts/original-eval.json
python tools/evaluate_boundary_challenge.py --output artifacts/boundary-eval.json
python -m streamlit run app.py
```

Results: baseline 58 tests and original 12 cases passed. Challenge before fix:
4/12 expectations matched, all 8 unsafe examples accepted, 0/4 safe examples
rejected. After fix: 59 tests passed, original 12/12 and challenge 12/12;
0/8 unsafe examples accepted, 0/4 safe examples rejected. Both fixture suites
make zero model calls. They are authored development regression sets, not a
holdout set and not a measurement of real model accuracy.

## Continuation: claim review implemented

Added review_records.py and a claim-review tab for local inference cards and
valid AI interpretations. Users can record support, partial support, lack of
support, or insufficient evidence. Support judgements require a real cited
source, locator and rationale; insufficient evidence requires missing material.
Meaningful question/scope/data/mode/provider/model/policy/content changes make
old reviews stale while preserving history. Visual filtering does not. Same
claim revisions preserve superseded judgements. JSON and Markdown include the
current and historical user-authored record; nothing becomes system-verified.

Full local suite: 69 methods passed, including 10 added review tests. Existing
12-case and new 12-case validator regressions still apply. Browser QA completed
2026-10-30: save a clearly marked functional-test review and download its JSON;
question-change invalidation is checked by AppTest. The exported example is a
functional test, not a participant judgement or a verified research conclusion.
Real model evaluation, independent human labels and user experiments remain
outstanding. Session review history is not durable storage; export before exit.

The public app on the audit date produced one observed failed generation:
two sequential attempts, main-model overload then backup output validation
failure with unknown_citation, followed by explicit rule fallback. This
does not contradict earlier documented successful calls or establish a rate.
