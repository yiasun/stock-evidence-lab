# 证据镜 · Stock Evidence Lab

## 从一个研究问题，走到可核对的证据

提交演示版 v3.0 · 2026-10-16

面向希望追问证据的个人研究者，以贵州茅台为单标的，把财务事实、分析推断和未知拆开呈现。产品帮助用户继续研究，不给股票好坏标签，不输出买卖、仓位或目标价。

## 要解决的问题

研究者通常能找到数字，却难以判断一句解释来自哪里、财务口径是否一致、相反证据是否被忽略。现金流上升与利润下降可以同时发生；一段流畅的总结不足以证明因果。

证据镜把任务收窄为：提出问题，选择研究维度，检查事实与矛盾，沿字段、算式、原文和下一步任务继续核对。

## 最小完整链路

提出问题 → 生成诊断 → 核对引用 → 查看相反与缺失证据 → 记录待验证任务 → 导出研究笔记。

| 产品范围 | 当前交付 |
| --- | --- |
| 单标的研究 | 贵州茅台，经营、财务、估值、行情、行业及事件六个维度 |
| 可追溯证据 | 十二张证据卡、五个来源，区分事实 / 推断 / 未知 |
| AI与程序分工 | AI选择证据并做定性解读；程序计算财务与行情指标 |
| 用户继续研究 | 引用展开、研究任务清单、JSON与Markdown笔记导出 |

## 为什么在这里使用AI

自然语言问题表达多样，AI可帮助关联不同维度、解释矛盾并提出继续核对的问题。数字计算与来源边界保持确定性，模型失败时仍能研究本地证据。AI不是替代数据库，也不替用户完成投资决策。

# 证据、口径与数据边界

财务观察期为2026H1，对比2025H1；行情快照截至2026-10-15。产品不会在启动时抓取实时行情，也不将冻结数据描述为当前实时状态。

| 来源 | 核验与用途 |
| --- | --- |
| S1 · 贵州茅台2026年半年报 | 巨潮原始PDF关键页5、7：财务数据与现金流解释，未经审计 |
| S2 · 价格调整公告 | 中国证券报披露；调价生效晚于半年报期末，不反推解释上半年 |
| S3 · 腾讯证券冻结日线 | 二十七个观测点；日期、原始响应哈希、不复权及成交量转换留痕 |
| S4 · 贵州茅台2025年年报 | 第6页归母利润，用于全年减去年同期再加本期的TTM试算 |
| S5 · 五粮液2026年半年报 | 第6、7页；同期限对比，仅两家公司定向样本 |

## 三条不能省略的口径

- 归母净利润与合并经营现金流不是同一口径，现金流包含财务公司资金变化。
- 历史PE/PB使用收盘价、半年期末股本和净资产，尚未核验至估值日的股本变化，只是有假设的试算。
- 行情区间价格变化不含股息；样本最大回撤不证明完整交易日覆盖，也不等于投资总回报。

## 如何防止证据被“补全”

字段缺失、期次错误、哈希不符与异常行情会停止对应计算。未知卡明确保留缺口；无来源的继承行情被隔离在沙盒，不进入公司事实。没有连接扶摇或iFinD，不声称使用其授权数据。

原始链接、页码、字段、SHA-256与剩余核验事项见仓库docs/DATA_VERIFICATION.md及data/evidence.json。

# AI协作方式与工程取舍

## 一次诊断如何产生

用户问题 + 所选维度 → 已核对证据卡 → 官方模型接口 → 本地结构与引用校验 → 分段解读 / 明确回退 → 研究记录导出。

| 层次 | 责任 |
| --- | --- |
| diagnosis.py | 同比、毛利率、行情回撤与估值试算；财务口径和数据完整性校验 |
| ai_layer.py | 官方接口、JSON格式、已知ID引用、研究边界；调价时序与已知错误案例检查 |
| request_gate.py | 同密钥单请求；五分钟成功缓存；限流、超时或过载后的冷却 |
| app.py / research_export.py | 用户控制范围、核对来源、任务状态、完整引用与可读笔记 |

## 免费服务的可靠性处理

智谱主模型为GLM-4.7-Flash。只有明确返回1305服务过载时，才顺序尝试一次官方免费GLM-4-Flash-250414；超时、账户限流、认证或额度错误不触发备用。页面和导出显示实际模型，不切换付费模型，不循环重试。

真实联调观察过1302账户限流、1305平台过载、超时与输出不合格。已实测主模型成功、免费备用成功及缓存命中。本次提交版备用成功耗时8.5秒；这是单次观察值，不是延迟承诺。

## 质量检查及其限度

自动化覆盖财务、异常输入、引用、回退、并发、缓存与页面主链路。另有十二个离线固定样本，核对已知好坏输出能否被正确接纳或拒绝，包含真实观察到的“用此前现金流推断调价影响有限”错误。

离线校验不是模型准确率评测，也不构成完整事实核验。无效段落可被隐藏，界面明确标示只保留通过校验的部分。AI推断始终需要沿原文复核。

# 验收、交付与下一步

## 如何复现

安装requirements.txt后运行：python -m streamlit run app.py。无需密钥可完成规则主链路；智谱配置只需AI_PROVIDER="zhipu"和服务端ZHIPU_API_KEY。密钥不进入仓库、研究笔记或报告。

自动检查：python -m unittest discover -s tests -v。离线校验：python tools/evaluate_analysis.py。测试报告区分本地模拟、云端CI与公网真实模型验收，不互相冒充。

## 三分钟演示顺序

先展示问题与财务矛盾，再生成解读、核对一条引用，切换调价问题说明未知，最后展示历史估值假设与研究笔记导出。免费服务拥堵时展示明确回退，不使用录制内容冒充实时返回。

## 明确保留的限制

单标的、冻结数据、两家公司样本；没有实时行情、估值日实际股本核验、历史估值分位、公告监控、自动财报解析或多标的支持。视频录制不属于本次必需交付，当前提供可直接录制的脚本。

后续优先级：先做更多真实问题的人工解读评审，再扩充数据更新能力；在已有证据链可复核的前提下扩展标的。产品价值在于让结论可以被继续追问，而非生成更确定的措辞。
